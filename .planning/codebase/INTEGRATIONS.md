# External Integrations

**Analysis Date:** 2026-10-21

## APIs & External Services

**Deals (Flipp):**
- Flipp (Wishabi) flyer/deal data - fetched by the service on a schedule
  - Client: custom HTTP client in `apps/service/src/deals/flipp/flipp-deal-source.ts` (base `https://backflipp.wishabi.com`), behind one rate-limited queue in `apps/service/src/deals/flipp/request-queue.ts`
  - Auth: none (public endpoint)
  - Test seam: `HEARTH_FLIPP_FIXTURE_DIR` / `HEARTH_FLIPP_FIXTURE_NOW` swap in fixtures (`apps/service/src/deals/flipp/normalized-fixtures.ts`)
  - Images: browser loads from `f.wishabi.net` and `images.wishabi.net` (allowed in the CSP in `docker/Caddyfile`)

**Recipe import (arbitrary web sites):**
- User-supplied recipe URLs are fetched by the service and parsed (JSON-LD and HTML via cheerio)
  - Client: `apps/service/src/recipes/fetch-recipe.ts` using `node:https` / `node:http`
  - SSRF guard: protocol restricted to http/https; DNS resolved with `node:dns/promises` and requests refused for disallowed resolved addresses (`resolveAllowedAddresses`)
  - Per-host throttling: `apps/service/src/recipes/host-rate-limiter.ts`
  - Test seam: `HEARTH_RECIPE_FIXTURE_DIR`

**Web Push:**
- Browser push services (endpoints supplied by each subscription) via VAPID-signed requests
  - SDK: `web-push` 3.6.7 in `apps/service/src/push/web-push-transport.ts`
  - Auth: VAPID key pair (`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, optional `VAPID_SUBJECT`); the public key is also built into the web app as `VITE_VAPID_PUBLIC_KEY`
  - Client subscription: `apps/web/src/lib/push/push-port.ts`, service worker handlers `apps/web/src/lib/push/service-worker-handlers.ts`
  - E2E double: `HEARTH_PUSH_TRANSPORT=test-double` with the seam in `apps/service/src/push/test-seam.ts`

**Fonts, icons, and other assets:**
- No third-party font or CDN loads detected in source; assets are self-hosted through Vite and the PWA precache.

## Data Storage

**Database:**
- PostgreSQL 17 (Supabase Postgres build `public.ecr.aws/supabase/postgres:17.6.1.167`)
  - Service connection: `DATABASE_URL`, login role `hearth_service` (password `HEARTH_SERVICE_DB_PASSWORD`), migration `supabase/migrations/20260919060000_hearth_service_role.sql`
  - Pool: `pg` `Pool` in `apps/service/src/db.ts` (DATE values returned as strings)
  - Client: Kysely 0.29.6; typed schema `apps/service/src/db/types.ts` (generated by `kysely-codegen`, `pnpm db:types`)
  - Per-request isolation: `apps/service/src/db/user-db.ts` opens a transaction, `set local role authenticated`, and installs the caller's JWT claims so RLS applies
  - Privileged access: `service_role` used only under `apps/service/src/privileged/`
  - Schema and RLS: `supabase/migrations/*.sql`; config `supabase/config.toml`
  - Seed tooling: `supabase/seed/` (`pnpm db:seed` requires `psql`)

**Realtime change feed:**
- Supabase Realtime `public.ecr.aws/supabase/realtime:v2.130.0` (WebSocket)
  - Client: `apps/web/src/lib/realtime/supabase-realtime.ts`, hook `apps/web/src/lib/realtime/use-list-realtime.ts`; one channel per list named `list:<listId>`
  - Publication setup: `supabase/migrations/20260919070300_realtime.sql`
  - Allowed by CSP `connect-src wss://{HEARTH_HOST}` in `docker/Caddyfile`

**File Storage:**
- Local filesystem only for backups (`BACKUP_DIR`, second disk). No object storage detected.

**Backups:**
- `prodrigestivill/postgres-backup-local:17-debian-d257e5d` container, daily dump at `0 2 * * *`; retention 14 days, 8 weeks, 6 months (per project docs)

**Caching:**
- Browser-side: TanStack Query cache persisted to IndexedDB via `idb-keyval` (`apps/web/src/lib/offline/persist.ts`, `apps/web/src/lib/api/query-client.ts`)
- Service-side: none external; in-memory structures only (skip rates, Flipp queue, recipe host limiter)

## Authentication & Identity

**Auth Provider:**
- Supabase GoTrue `public.ecr.aws/supabase/gotrue:v2.196.0` (self-hosted)
  - Browser client: `@supabase/supabase-js` 2.116.0 in `apps/web/src/lib/auth/auth-client.ts` (lazy-loaded via dynamic import)
  - Service-side GoTrue HTTP client: `apps/service/src/gotrue/client.ts` (sign-up, password verification with client IP, admin operations); `GOTRUE_URL` validated as http(s) in `apps/service/src/env.ts`
  - Admin email change: `apps/service/src/privileged/gotrue-admin.ts` (uses `SERVICE_ROLE_KEY`)
  - Token verification: `apps/service/src/auth/jwt.ts` (JWT verify, JWKS); `JWT_SECRET` must be at least 32 characters
  - Keys: `ANON_KEY` and `SERVICE_ROLE_KEY` (Kong key-auth consumers `anon` and `service_role` in `docker/kong.yml`)
- Magic-link sign-in: optional, toggled at build time by `VITE_MAGIC_LINK_ENABLED`
- Password rules and common-password list: `packages/shared/src/data/common-passwords.ts` (imported as `@hearth/shared/common-passwords`)
- Operator password reset: `apps/service/src/cli.ts` via `hearth-admin` (`apps/service/bin/hearth-admin`)

**API auth:**
- Service requests carry a bearer token; `apps/service/src/http/context.ts` authenticates and binds claims for `asUser` / `inHousehold`

## API Gateway

**Kong `kong/kong:3.9.3`:**
- Config `docker/kong.yml`, entrypoint `docker/kong-entrypoint.sh`
- Routes Supabase Auth (`auth:9999`, `/auth/v1/*`) and Realtime (`realtime-dev.supabase-realtime:4000/socket`, WebSocket); `key-auth` and `acl` plugins enforce anon and service_role consumers

**Caddy (reverse proxy and static host):**
- `hearth-caddy` built from `docker/caddy.Dockerfile`; config `docker/Caddyfile`, entrypoint `docker/caddy-entrypoint.sh`
- Serves the PWA, proxies `/api/*` to `hearth-service:3000` and Supabase paths to Kong (`kong:8000`)
- Content-Security-Policy set in `docker/Caddyfile`
- Only published port: `127.0.0.1:8080`

## Monitoring & Observability

**Error Tracking:**
- No external error tracker (no Sentry, Datadog, or OpenTelemetry SDK detected)
- Server errors recorded in Postgres via `public.record_app_error` (called as `anon` through `withAnonDb`, `apps/service/src/services/errors.ts`, `apps/service/src/db/user-db.ts`); payloads scrubbed by `scrubErrorReport` in `packages/shared/src/scrub.ts`

**Logs:**
- Fastify logger (pino, enabled in production builds; disabled in tests via `logger: false`) with `LOG_LEVEL` in `apps/service/src/env.ts`; container logs via Docker Compose
- Web error reporting installed at startup from `apps/web/src/lib/error-reporting.ts` (called in `apps/web/src/main.tsx`); render errors caught by `apps/web/src/components/states/ErrorBoundary.tsx`

**Health:**
- `GET /api/health` used by the service container healthcheck in `docker/docker-compose.yml`
- System health view reads newest backup mtime from `BACKUP_DIR` (`apps/service/src/privileged/service-role-db.ts`)

## CI/CD & Deployment

**Hosting:**
- Single self-hosted Linux host running Docker Compose (`docker/docker-compose.yml`, project name `hearth`)
- Public ingress via Tailscale Funnel: `sudo tailscale funnel --bg http://127.0.0.1:8080`, origin `https://<machine>.<tailnet>.ts.net`
- Pinned origin is part of PWA and push subscription identity (see `README.md`)

**Container registry:**
- `docker/login-action@v4` logs in to `ghcr.io` in `.github/workflows/ci.yml` (E2E image pulls; Supabase images also available from the `ghcr.io/supabase` mirror); runtime images from `public.ecr.aws` (Supabase), Docker Hub (`kong`, `prodrigestivill/postgres-backup-local`)

**CI Pipeline:**
- GitHub Actions: `.github/workflows/ci.yml` (lint, typecheck, unit, integration with Supabase CLI, Playwright E2E, build)
- Deploy: `.github/workflows/deploy.yml` on `workflow_run`, self-hosted runner (`self-hosted`, `hearth`), executes `scripts/deploy.sh`
- Dependency updates: `.github/dependabot.yml` (npm, GitHub Actions, Docker; weekly)
