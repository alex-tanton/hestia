## 3. Cross-Phase Integration Analysis

The cross-phase integration inspection confirmed complete cohesion across monorepo boundaries:

1. **Rebrand Propagation (Phase 8 → 9, 10, 11)**:
   - `HESTIA_*` environment prefix strictly required across all services; legacy prefix triggers runtime failure.
   - All 7 packages renamed to `@hestia/*` with lockfile cleanly resolving.
   - Database service role migrated cleanly to `hestia_service`.
   - Administrative CLI `apps/service/bin/hestia-admin` provides unified operator entry point (`hestia-admin reset-password`, `hestia-admin test-push`).

2. **Domain & Network Integration (Phase 9 → 10, 11)**:
   - Base origin `https://hestia.aberrance.app` binds GoTrue URLs (`GOTRUE_SITE_URL`, `GOTRUE_URI_ALLOW_LIST`, `GOTRUE_JWT_ISSUER`).
   - Caddy ingress reverse-proxies `/auth/v1/*` to Kong/GoTrue, `/api/*` to `hestia-service`, and serves static magic link templates directly from `/srv/templates/magic_link.html`.
   - Caddy passes client IP from `CF-Connecting-IP` alone; downstream service logs reflect real client addresses.
   - Content Security Policy `connect-src 'self' wss://hestia.aberrance.app` enforces zero unauthorized websockets or external dependencies.

3. **Email & Push Notification Pipelines (Phase 10 & 11)**:
   - Passwordless authentication operates via GoTrue SMTP (`smtp.resend.com:465`) under sender `auth@aberrance.app`.
   - Public visitor signups disabled (`GOTRUE_DISABLE_SIGNUP: 'true'`), preserving invited household member security.
   - Web Push tokens signed strictly with RFC 8292 `VAPID_SUBJECT: mailto:admin@aberrance.app`.
   - Operator CLI subcommand `hestia-admin test-push --email <email>` immediately verifies push delivery and prunes expired subscriptions (`gone`).
