## Phase Goal

ROADMAP goal (verbatim): "Rebrand the application from Hearth to Hestia across the monorepo, UI, manifest, CLI, and configuration."

This plan is the first slice: the data-bearing login role, the one rename that edits applied migrations, together with the narrow gate exemption that admits exactly that edit (D-05, D-06). Later plans sweep packages (08-02), environment and infrastructure (08-03), the user-facing brand, CLI and browser keys (08-04), the remainder and docs (08-05), align the planning text and write the owner checklist (08-06), and add the no-old-name guard and the full-stack proof (08-07).

<objective>
Rename the service login role `hearth_service` to `hestia_service` end to end (migration, login SQL, Compose, deploy script, seed, test stack, docs), and teach `scripts/check-migrations-append-only.mjs` a content-pinned, self-expiring exemption so the in-place edit of the two applied migrations passes CI while every other migration edit still fails.

Purpose: D-05 renames the role by editing applied migrations; D-06 requires that the blocking append-only gate admit exactly that edit, tested, and go back to strict on its own.

Output: the gate's `--exemptions` flag and its tests, `scripts/migration-exemptions.json`, the renamed role files, a green gate run against `origin/main`, a green role integration run on a fresh local Supabase, and docs for the exemption and the local reset.

Scope note (why 34 files is not a risk here): apart from the gate, its tests, the JSON file and five doc paragraphs, every file changes only through the scripted DB class (two `git mv` and four exact tokens), and those readers must change in the same commit as the role they log in as. The blob pins, the residual count and the fresh-database integration run check that one substitution as a whole.
</objective>

## Exemption contract

`scripts/migration-exemptions.json` is a JSON array. Each entry has exactly these string keys:

| Key | Rule |
|-----|------|
| `fromPath` | the migration's path at the merge base; starts with `supabase/migrations/`, ends with `.sql`, no `..` segment, no backslash |
| `toPath` | its path at HEAD, same rules; equal to `fromPath` for an edit, different for a rename |
| `fromBlob` | 40 lowercase hex digits: `git rev-parse <mergeBase>:<fromPath>` must equal it |
| `toBlob` | 40 lowercase hex digits: `git rev-parse HEAD:<toPath>` must equal it |
| `reason` | non-empty text |

An entry applies only when both blobs match and the change list has exactly its changes: `M fromPath` for an edit; `D fromPath` and `A toPath` for a rename. Applied entries remove those changes from the problem list and print `exempt: <fromPath> -> <toPath>: <reason>` on stdout. An entry that does not match is inert and prints nothing (that is the self-expiry). Summary: unchanged when no entry applies; otherwise `migrations: <A> added, nothing else changed, <N> exempt` (A counts additions not consumed by an entry, N applied entries) or the unchanged `migrations: <P> problems` line. Any unreadable present file, invalid JSON or invalid entry exits 2.
