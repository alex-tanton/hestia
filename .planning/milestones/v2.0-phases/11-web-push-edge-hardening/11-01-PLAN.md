## Phase Goal

ROADMAP goal (verbatim): "Ensure reliable Web Push notifications on real HTTPS mobile devices, configure Cloudflare edge performance/security, and lock in quality gates."

This plan establishes strict RFC 8292 compliance (`PUSH-01`) by enforcing that `VAPID_SUBJECT` is strictly required in `apps/service/src/env.ts`, validated as a syntactically correct contact URI (`mailto:<email>` or `https:` URI), and wired across all container manifests, secret generation scripts, E2E harnesses, and documentation with default value `mailto:admin@aberrance.app`.

<threat_model>
### Security Threat Model (ASVS L1)
- **T-11-01** (ASVS 2.1.1 / PUSH-01): Missing or malformed VAPID contact claim leading to push rejection or silent drops by APNs / Mozilla Autopush.
  - Threat: Push endpoints (specifically Apple Push Notification Service on iOS Safari and Mozilla Autopush on Firefox) reject or drop notifications when the VAPID JWT `sub` claim is absent, invalid, or an unencrypted `http://` URI.
  - Mitigation: Require `VAPID_SUBJECT` strictly in `envSchema` with `isContactUri` Zod refinement. Service refuses to start if missing, empty, or not a valid `mailto:<email>` or `https:` URI.
  - Test: `apps/service/src/env.test.ts` validates strict rejection of missing, empty, plain-text, and `http://` subjects.
- **T-11-02** (ASVS 13.1.1 / PUSH-01): Information disclosure of environment secrets or private email addresses in startup exception logs.
  - Threat: If environment validation fails on a malformed `VAPID_SUBJECT`, unhandled error traces might echo sensitive host configuration, credentials, or household data to standard error.
  - Mitigation: Validation error message strictly states `"VAPID_SUBJECT must be a mailto: or https: URI"` without echoing the provided invalid input or adjacent environment variables.
  - Test: `apps/service/src/env.test.ts` asserts that the thrown exception message does not contain the invalid test payload.
</threat_model>
