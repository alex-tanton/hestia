# External Integrations

**Analysis Date:** 2026-10-22

## APIs & External Services

**Flipp (grocery flyer and deal data):**
- Used for: pulling current flyer items for the Deals pillar
- Endpoint: `https://backflipp.wishabi.com` (`BASE_URL` in `apps/service/src/deals/flipp/flipp-deal-source.ts`); unauthenticated GET requests returning JSON
- Client: hand-written `fetch` in `apps/service/src/deals/flipp/request-queue.ts`, which serializes all calls through one rate-limited queue
- Auth: none
- Test seam: `HEARTH_FLIPP_FIXTURE_DIR` swaps in `apps/service/src/deals/flipp/fixture-transport.ts` for E2E; never set in production
- Image hosts: image URLs are served from `https://f.wishabi.net` and `https://images.wishabi.net`. These are allowed by the CSP `img-src` (`docker/Caddyfile`) and cached by the service worker (`apps/web/src/sw.ts`). `http://` image URLs are rewritten to `https://` (`flipp-deal-source.ts`).

**Recipe websites (recipe import):**
- Used for: fetching a pasted recipe URL and reading its JSON-LD (`apps/service/src/recipes/fetch-recipe.ts`, `json-ld.ts`)
- Client: Node `fetch` plus `cheerio` for HTML parsing
- Guards: private, loopback, and link-local addresses are refused (`apps/service/src/recipes/private-address.ts`); per-host rate limiting (`apps/service/src/recipes/host-rate-limiter.ts`)
- Test seam: `HEARTH_RECIPE_FIXTURE_DIR` swaps the fetch step for checked-in pages (`apps/service/src/recipes/fixture-fetch.ts`); never set in production

**Web Push services:**
- Used for: delivering notifications to subscribed browsers
- Client: `web-push` 3.6.7 in `apps/service/src/push/web-push-transport.ts`, with VAPID claims set from `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, and the derived subject (`apps/service/src/env.ts`, `vapidSubjectFor`)
- Endpoints: each browser's push-service URL, stored per subscription; these are not fixed hosts
- Test seam: `HEARTH_PUSH_TRANSPORT=test-double` selects `apps/service/src/push/recording-transport.ts`, which contacts no push service; only the E2E overlay sets it
- Browser side: `apps/web/src/lib/push/` subscribes with `VITE_VAPID_PUBLIC_KEY`; `apps/web/src/lib/push/service-worker-handlers.ts` displays messages

## Data Storage

**Primary database:**
- PostgreSQL 17 (Supabase build `public.ecr.aws/supabase/postgres:17.6.1.167` in production; `supabase/config.toml` `major_version = 17` locally)
- Service connection: `DATABASE_URL` as login role `hearth_service` (`postgresql://hearth_service:...@db:5432/postgres` in `docker/docker-compose.yml`); the password is supplied by `HEARTH_SERVICE_DB_PASSWORD`
- Pool and client: `pg` 8.23.0 through Kysely 0.29.6 (`apps/service/src/db.ts`)
- Per-request role switching: `apps/service/src/db/user-db.ts` opens a transaction, runs `set local role authenticated`, and installs the caller's JWT claims so RLS applies. A separate `withAnonDb` handles error recording as `anon`.
- Privileged access as `service_role` is confined to `apps/service/src/privileged/service-role-db.ts`
- Schema and policies: `supabase/migrations/` (8 files). RLS is defined in `supabase/migrations/20260919070100_rls.sql`.
- Typed schema: `apps/service/src/db/types.ts`, generated by `kysely-codegen` (`pnpm db:types`)
- Bootstrap SQL for production: `docker/db/roles.sql`, `docker/db/jwt.sql`, `docker/db/realtime.sql`, `docker/db/hearth-service-login.sql`, mounted into the `db` container's init directories

**Backups:**
- `prodrigestivill/postgres-backup-local:17-debian-d257e5d` service `backup` in `docker/docker-compose.yml`
- Daily dump at `0 2 * * *` (UTC) to `${BACKUP_DIR}`; retains 14 days, 8 weeks, and 6 months
- `hearth-service` mounts the same directory read-only (`BACKUP_DIR: /backups`) so System health can report the newest backup time

**File storage:**
- Local filesystem only, for backups and the built PWA. Supabase Storage is disabled (`[storage] enabled = false` in `supabase/config.toml`).

**Caching:**
- No external cache service. Browser-side caching: TanStack Query persisted to IndexedDB via `idb-keyval` (`apps/web/src/lib/offline/persist.ts`); service-worker caching in `apps/web/src/sw.ts`
- In-process state in the service: deal skip rates (`apps/service/src/services/skip-rates.ts`), Flipp request queue, recipe host rate limiter

## Authentication & Identity

**Auth provider:**
- Supabase GoTrue v2.196.0 (`public.ecr.aws/supabase/gotrue:v2.196.0`), self-hosted in Compose as service `auth` on port 9999
- Config is supplied through `GOTRUE_*` environment variables in `docker/docker-compose.yml`. Email and password sign-in is enabled; phone is disabled; anonymous users are disabled; `GOTRUE_MAILER_AUTOCONFIRM` is `true`; minimum password length is 8. No `GOTRUE_SMTP_*` settings are present while magic link is disabled.
- Issuer and site URL come from `HEARTH_ORIGIN`. JWTs are HS256, signed with `JWT_SECRET`, audience `authenticated`.
- Browser client: `@supabase/supabase-js` in `apps/web/src/lib/auth/auth-client.ts`, which talks to `/auth/v1` on the same origin
- Anon key: `VITE_SUPABASE_ANON_KEY` is public by design and is sent as `apikey` to Kong

**Service-side verification:**
- `apps/service/src/auth/jwt.ts` verifies bearer tokens (HS256 with `JWT_SECRET`)
- `apps/service/src/gotrue/client.ts` and `apps/service/src/gotrue/http.ts` call GoTrue at `GOTRUE_URL` (`http://auth:9999` in Compose) for signup, user update, and admin operations
- Admin operations: `apps/service/src/privileged/gotrue-admin.ts` uses `SERVICE_ROLE_KEY`; it is reached only by `main.ts` and `cli.ts`

**Gateway allowlist (Kong):**
- `docker/kong.yml` exposes only: `/auth/v1/token` (POST), `/auth/v1/logout` (POST), `/auth/v1/verify` (GET, POST), and the Realtime route. All other `/auth/v1` paths hit a denied route.
- Consumers `anon` and `service_role` are keyed by `SUPABASE_ANON_KEY` and `SUPABASE_SERVICE_KEY`, substituted by `docker/kong-entrypoint.sh`
- Caddy refuses `POST /auth/v1/signup*` and `PUT /auth/v1/user*` with 403 (`docker/Caddyfile`); sign-up and password change go through `hearth-service` (`/api/signup` in `apps/web/src/lib/auth/auth-client.ts`)

**Realtime:**
- Supabase Realtime v2.130.0 (`public.ecr.aws/supabase/realtime:v2.130.0`), service `realtime` in Compose
- Reached through Caddy at `/realtime/v1` and Kong; the tenant alias is `realtime-dev.supabase-realtime`
- Client: `apps/web/src/lib/realtime/supabase-realtime.ts`, one channel per open shopping list, delivering row-change notices that trigger TanStack Query refetches

**Email:**
- Not configured. Magic link (`VITE_MAGIC_LINK_ENABLED`, `HEARTH_MAGIC_LINK_ENABLED`) is off by default; no SMTP relay is set up.

## Monitoring & Observability

**Error tracking:**
- No third-party service. Server errors are recorded to Postgres through `public.record_app_error` via `recordAppError` (`apps/service/src/services/errors.ts`), scrubbed by `scrubErrorReport` in `packages/shared/src/scrub.ts`
- Client errors are posted to `/api/client-error` (`apps/web/src/lib/error-reporting.ts`)

**Logs:**
- Fastify logger (pino) at `LOG_LEVEL`, default `info`. Compose sets `LOG_LEVEL: info`.
- All containers use `json-file` logging with `max-size: 10m` and `max-file: 5`
- Caddy writes JSON access logs to stdout; Kong writes `combined` access logs to stdout
- Health endpoint: `GET /api/health` (checked by the `hearth-service` healthcheck in Compose)

## CI/CD & Deployment

**Hosting:**
- Self-hosted single host running Docker Compose; deploy script `scripts/deploy.sh`
- Public ingress: Tailscale Funnel forwards to `127.0.0.1:8080` (`sudo tailscale funnel --bg http://127.0.0.1:8080`). Origin is `https://<machine>.<tailnet>.ts.net`, which is pinned and baked into installed PWAs and push subscriptions.

**CI pipeline (`.github/workflows/ci.yml`, GitHub-hosted runners):**
- Seven jobs, each with a timeout: `lint` (`pnpm lint`, `pnpm format:check`), `typecheck`, `test-unit` (`pnpm test:harness`, the non-web workspaces' tests, then `pnpm --filter @hearth/web test:coverage`), `test-integration` (`supabase start`, a `pnpm db:types` drift check, then `pnpm --filter @hearth/service test:coverage`), `test-e2e` (pull requests and `main`, `pnpm test:e2e`), `build` (`pnpm build`), `hygiene` (`pnpm knip`, `node scripts/check-knip-baseline.mjs`, `pnpm jscpd`, `node scripts/audit-prod.mjs`, `node scripts/check-repo-hygiene.mjs`, `node scripts/check-migrations-append-only.mjs`, each its own step)
- `Sweep` (`.github/workflows/sweep.yml`, a separate workflow): the date and time-zone test matrix on pushes to `main` that change more than `docs/` and `.planning/`, nightly, and on demand; it gates nothing and triggers no deploy
- Actions: `actions/checkout@v7`, `pnpm/action-setup@v6`, `actions/setup-node@v7`, `supabase/setup-cli@v3` (CLI 2.117.0), `docker/login-action@v4`, `actions/upload-artifact@v7`
- Optional Docker Hub login uses repository secrets `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN`; GHCR login uses `GITHUB_TOKEN`
- Image pre-pull: `scripts/ci-prepull-images.sh` pulls the Compose and Dockerfile images, with the Supabase images from `ghcr.io/supabase` and fallback to `public.ecr.aws`

**Deploy (`.github/workflows/deploy.yml`):**
- Triggered by `workflow_run` on CI completing for `main`, only on successful push events; runs on the self-hosted runner `[self-hosted, hearth]`
- Asks `scripts/deploy-gate.sh` first: it deploys when anything outside `docs/` and `.planning/` changed since the revision of the running `hearth-service` image, never deploys a commit older than the running one, and redeploys a re-run of the running commit
- Then runs `scripts/deploy.sh` at the CI-tested commit (`HEARTH_DEPLOY_SHA`)

**Dependency updates:** Dependabot (`.github/dependabot.yml`), weekly, for npm, GitHub Actions, and Docker images

**Container registries:** `public.ecr.aws` (Supabase images), `kong/kong` and `prodrigestivill/postgres-backup-local` on Docker Hub, `caddy` and `node` base images, `ghcr.io/supabase` (CI mirror)

## Webhooks & Callbacks

**Incoming:**
- None from third parties. Inbound traffic is the PWA's `/api/*`, `/auth/v1/*`, and `/realtime/v1/*` calls through Caddy.
- `GET /api/health` for the container healthcheck
- Test-only route `apps/service/src/push/test-seam.ts`, registered only when `HEARTH_PUSH_TRANSPORT=test-double`

**Outgoing:**
- Flipp API calls (`https://backflipp.wishabi.com`) from `apps/service/src/deals/flipp/`
- Recipe page fetches to user-supplied URLs from `apps/service/src/recipes/fetch-recipe.ts`
- Web Push messages to browser push-service endpoints from `apps/service/src/push/web-push-transport.ts`
- GoTrue admin and auth calls to `GOTRUE_URL` from `apps/service/src/gotrue/` and `apps/service/src/privileged/gotrue-admin.ts`
- Scheduled jobs (`apps/service/src/jobs/`) run in-process and make no inbound callbacks
