## Task Goal

Fix WR-02 from the Phase 4 code review (`04-REVIEW.md`). The held deal-add id lives in a per-card hook instance, so a lost-response retry after the card unmounts (a filter change, paging, or navigating away and back) mints a new id and the deal lands twice. The owner asked for the id to be held at QueryClient scope (UAT item 4).

<objective>
Move `useAddDealToList`'s held-id map from a per-hook-instance React ref to a module-level `WeakMap` keyed by the `QueryClient`, so a retry survives the card unmounting (WR-02; FIX-01's own scenario). The key stays `${listId}:${dealId}`, only a success clears an id, and the hook's signature and the API contract do not change. The work is test-first: a new regression case is run red on origin/main's unchanged hook, then green after the fix.

Planner finding (the threat-model check the orchestrator asked for): the app never clears its QueryClient, neither on sign-out nor on a household switch. `apps/web/src/main.tsx:30` builds one client for the page. `apps/web/src/lib/auth/auth-client.ts:176-179` and `apps/web/src/screens/settings/AboutSection.tsx:25-32` only call supabase-js `signOut`. `useSwitchHousehold` and its siblings in `apps/web/src/lib/api/hooks.ts` only run `removeQueries({ queryKey: HOUSEHOLD_SCOPE })`. Nothing in `apps/web/src` outside tests calls `queryClient.clear()`. So ids held per QueryClient alone would survive one user signing out and another signing in on the same page. A "clear the map when the QueryClient is cleared" hook would never fire in this app (and TanStack has no single clear event to hook). This plan therefore also scopes the holder to the signed-in user, read from the auth client the hook's context already provides, and adds a guard test for that. All of this stays inside `deals.ts`, so no other file joins the diff.

Purpose: close WR-02 so the owner's PR can land a FIX-01 that covers its own scenario.
Output: branch `fix/held-deal-id` (worktree `../hearth-held-id`) pushed with the fix and two new tests. On the session branch, the ledger `.planning/cleanup/FIX-LEDGER-HELD-ID.md` and UAT item 4 are updated, committed and pushed. No pull request.
</objective>
