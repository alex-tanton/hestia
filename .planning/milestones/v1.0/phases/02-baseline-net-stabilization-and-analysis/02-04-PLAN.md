## Phase Goal

ROADMAP goal (verbatim): "The test suite passes deterministically on any weekday and household timezone, and a calibrated analyzer produces a triaged findings list, so removals can be attributed and trusted."

The goal is outcome-shaped but not written as a user story; it is not reframed here. Run `/gsd-mvp-phase 02` if a user-story framing is wanted.

<objective>
Fix the UTC-versus-household date helper in `bills.integration.test.ts` behind a regression guard that fails before and passes after, share zone-correct helpers, audit the other integration files that read the clock, and run the integration suite under the time-zone sweep.

Purpose: TIME-05, the integration half of TIME-02, and D-06 and D-07. The bills file's top-level `isoDate(offsetDays)` counts days on the UTC calendar while the default household is in America/New_York. Between 00:00Z and 04:00Z (05:00Z in winter) the two calendars differ by a day, so `isoDate(-1)` can be the household's today: a time-of-day flake that a weekday matrix would never find.

Why the guard is deterministic without pinning: Pacific/Kiritimati (UTC+14) has a different calendar date from UTC from 10:00Z onward, and Pacific/Pago_Pago (UTC-11) has a different date before 11:00Z. At every instant at least one of the two households straddles the UTC date. A UTC-dated helper therefore fails one of the guard's assertions at any hour of any day, and a zone-correct helper passes all of them.
Output: `zone-dates.ts` and its unit test, the fixed bills file, wired integration and coverage configs, and audited integration files, as two commits on `test/deterministic-clock`.

Scope note (12 files, inside the 10-or-more warning band, kept as one plan on purpose). Task 1's five files are two new helper files, the bills fix, and two one-entry config wirings. Task 2's seven files each swap one to four clock reads for a helper call. A separate plan for Task 2 would need a second Supabase session, and phase rule 9 allows only one integration plan at a time. It would also add another sequential wave on the same branch and worktree without any parallel work.
</objective>
