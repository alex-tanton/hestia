## Phase Goal

ROADMAP goal (verbatim): "Rebrand the application from Hearth to Hestia across the monorepo, UI, manifest, CLI, and configuration."

This plan finishes the live-file sweep of D-11 (every token class but the ones plans 08-01 to 08-04 moved) for every tracked file outside `.planning/`. Plan 08-06 runs in the same wave and hand-edits the planning text, the cloud tooling and the owner checklist; it shares no file with this plan, because this plan's selector excludes `.planning/` and 08-06 edits nothing else. Plan 08-07 then makes "no old name left" a CI gate.

<objective>
Run the final catch-all substitution over every live file outside `.planning/` after reading the residual list, and prove the tree still typechecks, lints, formats and passes every unit and harness test.

Purpose: D-11 (rewrite the name in all live files).

Output: one `chore:` sweep commit with zero residual outside `.planning/`.

Scope note (why 53 files in one task is not a risk here): every file changes only through one scripted catch-all substitution, which runs after every residual line has been sorted into the six categories, and Task 1 stops on any line that fits none of them. The substitution must land as one commit, because it moves writers and their readers together: the User-Agent built in `request-queue.ts:85` and asserted in `request-queue.test.ts:104`, the seed password that `supabase/seed/seed-users.ts:24` sets and `e2e/support/env.ts:95` signs in with, and the test database password default in `apps/service/src/test/service-stack.ts:33` and the docs lines that set it. A split by file group can leave a commit whose unit or E2E tests fail, or whose docs give a password the code no longer uses. Zero residual plus the full suite checks the sweep as a whole. The hand edits under `.planning/` are a separate concern and live in 08-06.
</objective>
