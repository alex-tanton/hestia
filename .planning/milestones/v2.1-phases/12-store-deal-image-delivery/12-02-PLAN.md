<objective>
Update PWA Service Worker image caching to intercept all allowed Flipp and Open Food Facts CDNs with an expanded 200-entry quota (D-03: scope strictly to remote HTTPS CDN domains), and refactor `DealImage.tsx` to use centralized validation from `@hestia/shared` with robust fallback placeholders.
</objective>

<context>
In Phase 12 Plan 01, `@hestia/shared` established `isAllowedImageUrl` and `ALLOWED_IMAGE_DOMAINS`, and `docker/Caddyfile` updated the Content-Security-Policy header. Plan 02 completes client-tier image delivery across the Workbox Service Worker and the React application UI.

Currently, `apps/web/src/sw.ts` only matches two origins (`https://f.wishabi.net` and `https://images.wishabi.net`) with a 100-entry cap, and `apps/web/src/screens/deals/DealImage.tsx` maintains its own duplicate origin list.

Per decisions D-01, D-02, and D-03:
- D-01: Centralize allowed image domain validation by importing `isAllowedImageUrl` from `@hestia/shared` into `sw.ts` and `DealImage.tsx`.
- D-02: Support modern Flipp subdomains and Open Food Facts image hosts with strict dot-subdomain suffix validation.
- D-03: Scope strictly to remote HTTPS CDN domains in `isAllowedImageUrl` and service worker caching, while local assets continue using standard Vite imports.
- Discretion: Increase Service Worker cache quota from 100 to 200 entries with 7-day TTL to comfortably support multi-circular weekly browsing.
</context>

<threat_model>
ASVS Level: 1
Block on: high

- **T-12-03: Service Worker cache poisoning and quota exhaustion.**
  - *Threat:* Malicious actors or arbitrary third-party requests could poison the `deal-images` Cache Storage or exhaust browser origin storage budgets.
  - *Mitigation:* Workbox route matcher in `apps/web/src/sw.ts` delegates URL validation to `isAllowedImageUrl(url)`, intercepting only approved HTTPS CDN domains. Storage exhaustion is prevented by `ExpirationPlugin({ maxEntries: 200, maxAgeSeconds: 7 * 24 * 60 * 60 })`, which enforces LRU eviction and automatic 7-day TTL pruning.
- **T-12-04: Cross-site scripting (XSS), mixed-content injection, and layout shifts from untrusted images.**
  - *Threat:* Untrusted `javascript:`, `data:`, or `http:` URLs in deal payloads could cause mixed-content blocks, tracking, or broken UI layout shifts.
  - *Mitigation:* `DealImage.tsx` validates URLs through `isAllowedImageUrl` before mounting `<img src={url} alt="" />`. Any null, invalid, unallowed, or failed (`onError`) image URL renders a fallback placeholder (`<ImageOff />`) within a layout-preserving container (`bg-raised shrink-0 overflow-hidden rounded-sm`), preventing layout shifts and XSS execution.
</threat_model>

<specless_assumptions>
- **IMG-02 (empty):** Empty strings, null, or undefined URLs passed to the Service Worker request matcher return false and are never routed to the `deal-images` cache.
- **IMG-02 (adjacency):** Allowed domain boundaries strictly match either the exact apex domain or a dot-prefixed subdomain (`.flipp.com`); strings sharing a suffix without a dot (e.g., `notflipp.com`) are rejected.
- **IMG-02 (ordering):** URL validation and Service Worker cache entries evaluate deterministically; identical URLs resolve to the same cache entry regardless of request arrival ordering.
</specless_assumptions>
