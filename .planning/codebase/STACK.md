## Configuration

**Environment:**
- Runtime configuration is read from process environment and validated by Zod in `apps/service/src/env.ts`; the service fails at startup on an invalid or missing variable
- The production env file lives outside the repository checkout at `/srv/hearth/.env` (passed to Compose via `--env-file`); `.env.example` at repo root documents every key
- Web build-time variables (Vite, `import.meta.env`): `VITE_SUPABASE_ANON_KEY`, `VITE_VAPID_PUBLIC_KEY`, `VITE_MAGIC_LINK_ENABLED` - injected as Docker build args in `docker/caddy.Dockerfile`
- Service variables (names only): `DATABASE_URL`, `HOST`, `PORT`, `LOG_LEVEL`, `HEARTH_TRUSTED_PROXIES`, `HEARTH_ORIGIN`, `HEARTH_OWNER_EMAIL`, `HEARTH_RATE_LIMIT_PER_MINUTE`, `GOTRUE_URL`, `JWT_SECRET`, `ANON_KEY`, `SERVICE_ROLE_KEY`, `BACKUP_DIR`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `HEARTH_PUSH_TRANSPORT`; E2E-only overrides `HEARTH_FLIPP_FIXTURE_DIR`, `HEARTH_FLIPP_FIXTURE_NOW`, `HEARTH_RECIPE_FIXTURE_DIR`
