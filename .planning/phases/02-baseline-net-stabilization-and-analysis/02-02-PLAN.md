## Phase Goal

ROADMAP goal (verbatim): "The test suite passes deterministically on any weekday and household timezone, and a calibrated analyzer produces a triaged findings list, so removals can be attributed and trusted."

The goal is outcome-shaped but not written as a user story; it is not reframed here. Run `/gsd-mvp-phase 02` if a user-story framing is wanted.

<objective>
Create the one clock pin and time-zone hook every workspace will share, plus the sweep runner that varies them, and prove the path end to end on the web suite: first the PR #1 failure (`favorites.test.tsx`), then all seven time-dependent web files.

Purpose: TIME-01, D-01 to D-03. The pin makes unit tests independent of the wall clock; the sweep proves they are independent of the weekday and the zone. Phase 6 (TIME-06) reuses the same env vars for the CI matrix.
Output: `test/clock-setup.mjs`, `test/global-tz.mjs`, `scripts/test-sweep.mjs`, the web test block wired to them, and the seven web test files fixed, as commits on `test/deterministic-clock` in `../hearth-clock`.

Design choice (Claude's discretion: name and location of the clock helper and the sweep script). The setup and the hook live once at the repo root in `test/`, written as `.mjs`, and every workspace's Vitest config points at them by relative path. Planner probes (Vitest 5.0.1) showed the following. They are Node and Vitest behaviors, not platform ones, and this plan's verify commands re-prove each one in the Linux session:
- A setup file outside a workspace resolves `vitest` and runs, and `expect.getState().testPath` gives the current test file at the setup file's top level.
- A top-level `vi.setSystemTime` plus a `beforeEach` re-pin covers module scope, `beforeAll` and the tests, and survives a test's `vi.useRealTimers()`.
- A local `vi.useFakeTimers({ toFake: ['Date'] })` plus `vi.setSystemTime`, `useFakeTimers({ now: 0 })` and `useFakeTimers({ shouldAdvanceTime: true })` all still work on top of the global pin.
- `TZ` passed through a Node `spawnSync` env reaches Vitest workers under both the forks and the threads pool; an invalid `TZ` silently falls back to UTC (zone `Etc/Unknown`), which is why the hook validates it.
- Root `.mjs` files in subfolders lint with no ESLint change, whereas a root `.ts` file fails with "not found by the project service". That is why these files are `.mjs` and not `.ts`.
Per-workspace copies would add five near-identical files (jscpd clones), and packages have no Node types for `process`.

Scope note (11 files, inside the 10-or-more warning band, kept as one plan on purpose). Task 1 creates three small root files, adds two entries to one config block, and fixes one test. Each of Task 2's six edits is a local fix of one classified kind (a or b) in a single test file, checked by the same web sweep. Every plan on `test/deterministic-clock` runs one after another in the single `../hearth-clock` worktree. Moving the six files into their own plan would add a wave and a SUMMARY hand-off but no parallel work, and the fixes would sit apart from the sweep run that proves them.
</objective>
