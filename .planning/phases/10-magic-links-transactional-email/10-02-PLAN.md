## Phase Goal

ROADMAP goal (verbatim): "Enable passwordless magic link authentication end-to-end with verified email delivery."

This plan upgrades the Web PWA front-end: enforcing `shouldCreateUser: false` in `auth-client.ts`, mapping uninvited email rejections to a helpful error message (`UNKNOWN_EMAIL_MESSAGE`), upgrading the sign-in entry point on `SignInScreen.tsx` to a prominent secondary button with an "or" divider while strictly maintaining the `check-build.mjs` tripwire string `"Email me a sign-in link"`, and proving code-splitting keeps the app shell well under the 200 KB gzipped budget.

<threat_model>
### Security Threat Model (ASVS L1)
- **T-10-04** (ASVS 2.1.2 / AUTH-01): Exposure of unauthenticated administrative functionality or unintended account creation via client error handling.
  - Threat: Web client permits uninvited user to submit form and displays misleading success feedback or leaks internal system state.
  - Mitigation: Client passes `shouldCreateUser: false`, catches GoTrue signup refusal, and displays safe generic error `UNKNOWN_EMAIL_MESSAGE` ("No account found with this email. Ask your household admin for an invite.").
  - Test: Vitest component test in `apps/web/src/screens/onboarding/magic-link.test.tsx` verifying rejection and error message rendering.
- **T-10-05** (ASVS 14.2.1 / AUTH-02): Denial of service or credential brute force due to missing client-side submission throttling.
  - Threat: Rapid repeated clicks on "Send sign-in link" or "Send a new code" trigger mail spam or rate limit exhaustion.
  - Mitigation: Enforce 30-second countdown cooldown timer on resend actions in `MagicLinkCodeScreen.tsx`.
  - Test: Vitest component test in `apps/web/src/screens/onboarding/magic-link.test.tsx` verifying resend button is disabled during countdown.
</threat_model>
