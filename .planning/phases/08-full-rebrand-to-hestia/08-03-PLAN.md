## Phase Goal

ROADMAP goal (verbatim): "Rebrand the application from Hearth to Hestia across the monorepo, UI, manifest, CLI, and configuration."

This plan delivers success criterion 5 ("Environment variables and Docker Compose services support `HESTIA_*` configuration") as a hard cutover (D-01, D-02) and the infrastructure names of D-03: two reviewable class commits.

<objective>
Rename every `*_` environment variable of the old prefix to `HESTIA_*` in one atomic commit, with tests proving the old names are rejected rather than read; then rename the Compose project, network, service, images, build cache id, host paths, E2E names, Supabase project id and the deploy runner label, proving the Compose files still resolve and merge to one network.

Purpose: Compose, the E2E overlay, scripts and `env.ts` must change together, or optional variables (trusted proxies, owner email, rate limit, push transport) silently fall back to defaults (RESEARCH Pitfall 1). The infrastructure names are data-bearing (D-03) and drive deploy-gate's running-revision lookup.

Output: an env commit and an infra commit, three new env tests, a resolved Compose config, green script and E2E-support tests, and the deployment doc's fresh-host and collision notes.

Scope note (why 46 files is not a risk here): the files change through two scripted class substitutions (ENV, INFRA); the hand-written part is three env tests and two doc paragraphs. Pitfall 1 requires every env reader and writer to change in one commit, so a split by file would open a window where optional variables silently fall back to defaults. The two `docker compose config` checks, the harness tests and the residual count check every file.
</objective>
