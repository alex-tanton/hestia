# Plan 13-01: Pricing Engine Mathematical Derivation & Sanity Thresholds

## Context

Hestia's deal pricing engine currently skips multi-item marketing promotions ("Buy 2 Get 1 Free", "Must buy 2", "Save $1.50 on 2") by returning `skip('buy_n_get_m')` or `skip('minimum_quantity')`. Furthermore, `discountPercent` uses `Math.floor` instead of standard half-up rounding, causing rounded discount values to drift (e.g. 49% instead of 50% on half-off odd bases).

This plan updates the arithmetic foundation in `apps/service/src/deals/money.ts` and `apps/service/src/deals/price/parse-price.ts`, and replaces outright skips in `apps/service/src/deals/price/parsers.ts` with mathematical derivations of effective unit prices and regular prices per locked decisions D-01, D-02, D-03, and D-04.

<threat_model>
### Security ASVS Level: 1 | Severity Threshold: HIGH

- **T-13-01 [Tampering/Integrity - ASVS V5 Input Validation]:** Price distortion or OCR errors in flyer feeds causing extreme negative prices, inverted discounts (`originalPrice <= unitPrice`), or absurdly inflated original prices (`originalPrice >= 10 * unitPrice` or discount > 95%).
  - *Mitigation:* `withoutImplausibleOriginal` strictly drops `originalPrice` to `null` if `originalPrice <= unitPrice`, `originalPrice >= unitPrice * 10`, or `((originalPrice - unitPrice) / originalPrice) > 0.95`. `discountPercent` clamps to 1%–95%.
- **T-13-02 [Denial of Service - ASVS V5 Error Handling]:** Division by zero or non-numeric NaN values in bundle division causing unhandled server exceptions during price parsing.
  - *Mitigation:* Divisors are guarded with integer validity checks (`count >= 2`), cent division uses `divideCents`, and non-positive counts return `null` instead of throwing.
- **T-13-SC [Supply Chain - ASVS V1 Architecture]:** Unauthorized package insertion or external rounding dependency tampering.
  - *Mitigation:* Pure TypeScript implementation with zero external npm dependencies; all math utilizes native `Math.round` and integer arithmetic.
</threat_model>

<action>
Update discount calculation and price sanity boundaries per D-03 and D-04.

1. In apps/service/src/deals/money.ts:
   - In function `discountPercent(unitPrice: number, originalPrice: number | null): number | null`:
     - If `originalPrice === null || originalPrice <= unitPrice`, return `null`.
     - Compute percentage using half-up cent rounding: `const pct = Math.round(((originalPrice - unitPrice) / originalPrice) * 100)`.
     - Enforce liberal discount threshold: if `pct < 1 || pct > 95`, return `null`. Otherwise return `pct`.

2. In apps/service/src/deals/price/parse-price.ts:
   - In function `withoutImplausibleOriginal(core: PriceCore): PriceCore`:
     - If `core.originalPrice !== null`:
       - If `core.originalPrice <= core.unitPrice`, return `{ ...core, originalPrice: null, discountPercent: undefined }`.
       - If `core.originalPrice >= core.unitPrice * 10`, return `{ ...core, originalPrice: null, discountPercent: undefined }`.
       - If `Math.round(((core.originalPrice - core.unitPrice) / core.originalPrice) * 100) > 95`, return `{ ...core, originalPrice: null, discountPercent: undefined }`.
     - If `core.discountPercent !== undefined && (core.discountPercent < 1 || core.discountPercent > 95)`:
       - Set `discountPercent: undefined`.
     - Return `core`.
   - In function `parsePrice(price: PriceCopy): PriceResult`:
     - Keep assignment: `discountPercent: core.originalPrice === null ? null : (core.discountPercent ?? discountPercent(core.unitPrice, core.originalPrice))`.

3. In apps/service/src/deals/price/parse-price.test.ts:
   - Add unit tests for `withoutImplausibleOriginal` and `discountPercent`:
     - Verify half-up rounding (e.g. unit 475, original 949 produces 50%, not 49%).
     - Verify original price equal to or less than unit price produces null original price and null discount.
     - Verify case pricing OCR mismatch (original >= 10x unit price) sets original price to null.
     - Verify discounts exceeding 95% off set original price to null.
     - Verify discounts between 1% and 95% are retained correctly.
</action>

<action>
Upgrade price parser implementations in apps/service/src/deals/price/parsers.ts to derive pricing math instead of skipping per D-01 and D-02.

1. Update `parseMultiBuy`:
   - Inspect bundle copy (`copy.pre`, `copy.offer`, `copy.story`).
   - Extract bundle item count from `copy.pre` using `(\d+) ?(?:\/|for\b)` (e.g., "2/" or "2 for"). If count < 2 or not integer, return `null`.
   - Check if copy contains bundle savings:
     - Regex for dollar savings: `/\bsave \$ ?(\d+(?:\.\d{1,2})?)(?:\s*(?:on|off|for)\s*(\d+))?\b/i`
     - Regex for cent savings: `/\bsave (?:at least )?(\d+)¢(?:\s*(?:on|off|for)\s*(\d+))?\b/i`
   - If savings is matched:
     - Determine savings in cents: `Math.round(Number(matchDollars) * 100)` or `Number(matchCents)`.
     - Check matched item count in savings phrase if present: if specified and does not equal bundle `count`, ignore savings and proceed with standard multi-buy logic.
     - If valid bundle savings:
       - `totalCents = copy.price.currentPrice`
       - `originalTotal = totalCents + savingsCents`
       - `unitPrice = divideCents(totalCents, count)`
       - `originalPrice = divideCents(originalTotal, count)`
       - `discountPercent = Math.round(((originalPrice - unitPrice) / originalPrice) * 100)`
       - Return `{ unitPrice, priceUnit: 'each', originalPrice, discountPercent }`.
   - If no bundle savings in text, retain existing multi-buy behavior:
     - `unitPrice = divideCents(total, count)`
     - `originalPrice = copy.price.originalPrice === null ? null : divideCents(copy.price.originalPrice, count)`
     - Return `{ unitPrice, priceUnit: 'each', originalPrice }`.

2. Update `parseBuyNGetM`:
   - Check `PARTIAL_BOGO.test(copy.offer)`. If true, return `skip('buy_n_get_m')`.
   - Check `BUY_N_GET_FREE`: regex `new RegExp(String.raw`\bbuy ?(?:any )?(\d+)\b[^.]{0,30}?\bget ?(?:any )?(\d+)\b[^.]{0,20}?\bfree\b`, 'i')`.
   - If matched:
     - `n = Number(freeMatch[1])`, `m = Number(freeMatch[2])`.
     - If `n === 1 && m === 1`, return `null` (delegating to `parseBogo`).
     - Retrieve base price: `base = copy.price.currentPrice ?? copy.price.originalPrice`.
     - If `base === null`, return `skip('buy_n_get_m')`.
     - Derive effective unit price:
       - `paidCount = n`
       - `totalCount = n + m`
       - `totalPaid = paidCount * base`
       - `unitPrice = divideCents(totalPaid, totalCount)`
       - `originalPrice = base`
       - `discountPercent = Math.round(((originalPrice - unitPrice) / originalPrice) * 100)`
       - Return `{ unitPrice, priceUnit: 'each', originalPrice, discountPercent }`.
   - Check `BUY_N_GET_AMOUNT`:
     - If copy has "buy N get $X off" (e.g. "BUY 2 GET $8.00 OFF", "Buy 2 Get 10.00 Off, SAVE $8.00 ON 2"):
       - Check base price: `base = copy.price.currentPrice ?? copy.price.originalPrice`.
       - If `base !== null`:
         - Extract `n` and amount off `amountCents`.
         - If `n >= 1 && (n * base) > amountCents`:
           - `totalPaid = (n * base) - amountCents`
           - `unitPrice = divideCents(totalPaid, n)`
           - `originalPrice = base`
           - `discountPercent = Math.round(((originalPrice - unitPrice) / originalPrice) * 100)`
           - Return `{ unitPrice, priceUnit: 'each', originalPrice, discountPercent }`.
       - If base price is absent, return `skip('buy_n_get_m')`.
   - Return `null`.

3. Update `parseMinimumQuantity`:
   - Match minimum quantity terms: `/\bwhen you buy\b|\bmust buy\b|\bbuy \d+ or more\b/i`.
   - If matched:
     - Check whether `copy.pre` matches multi-buy bundle patterns (e.g., `/\d+\s*(?:\/|for\b)/i.test(copy.pre)`): if true, return `null` so downstream `parseMultiBuy` handles bundle division rather than prematurely returning the un-divided bundle total.
     - Otherwise, check shelf price: `current = copy.price.currentPrice`.
     - If `current !== null`:
       - Return `{ unitPrice: current, priceUnit: 'each', originalPrice: copy.price.originalPrice }`.
     - If `current === null`, return `skip('minimum_quantity')`.
   - Return `null`.

4. In apps/service/src/deals/price/parse-price.test.ts:
   - Update tests that previously expected `skip('buy_n_get_m')` or `skip('minimum_quantity')` for items with prices to now expect derived prices.
   - Add test cases verifying:
     - "2/$6.00 with $1.50 off on 2": unitPrice 300, originalPrice 375, discountPercent 20%, displayPrice "2/$6.00".
     - "2/$6.00 with save at least 98¢ on 2": unitPrice 300, originalPrice 349, discountPercent 14%, displayPrice "2/$6.00".
     - "BUY 2 GET 1 FREE" at $1.99 each: unitPrice 133, originalPrice 199, discountPercent 33%.
     - "BUY 2 GET $8.00 OFF" at $19.99 each: unitPrice 1599, originalPrice 1999, discountPercent 20%.
     - "MUST BUY 2" over $1.95: unitPrice 195, priceUnit each.
     - "2/$6.00 MUST BUY 2": yields unitPrice 300 (via multi-buy bundle division) rather than un-divided 600.
     - "BUY 2 GET 3 Free!" with no price: returns `{ skipped: 'buy_n_get_m' }`.
</action>
