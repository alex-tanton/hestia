# Plan 13-02: Ingestion Concurrency, Pacing Queue & In-Memory LRU Cache

## Context

Dealingestion for an active postal code currently takes 13–15+ minutes because `apps/service/src/deals/flipp/request-queue.ts` serializes all requests one-by-one with a 500ms delay (`MIN_GAP_MS = 500`). For an 8-flyer postal code containing over 1,000 items, this sequential processing causes client polling to hit maximum retry attempts and time out. Furthermore, items shared between neighboring households or retried runs are repeatedly re-fetched over the network without caching.

This plan refactors `FlippRequestQueue` into a bounded concurrency worker pool (4–5 concurrent workers, 100–200ms pacing) and equips `FlippDealSource` with concurrent item resolution and an in-memory LRU item-detail cache (6-hour TTL, ~2,000 items) per locked decisions D-05, D-06, and D-07.

<threat_model>
### Security ASVS Level: 1 | Severity Threshold: HIGH

- **T-13-03 [Denial of Service - ASVS V5 Denial of Service / Rate Limiting]:** Upstream Flipp API rate-limiting, IP blocking, or HTTP 429/503 responses triggered by burst traffic during postal code ingestion.
  - *Mitigation:* Bounded concurrency worker pool capped at 4 concurrent workers with 150ms minimum dispatch gap pacing (`minGapMs`) and exponential backoff on retries.
- **T-13-04 [Race Condition / Concurrency Integrity - ASVS V5 State Management]:** Race condition across concurrent workers during circuit breaker transitions, leading to missed failure counts or zombie requests executing after breaker trip.
  - *Mitigation:* `isOpen` evaluated synchronously before dispatch and inside queue drain loop; tripping the breaker flushes and rejects all pending queued tasks with `CircuitOpenError`.
- **T-13-05 [Denial of Service - ASVS V5 Memory Management]:** Unbounded memory growth from caching flyer item details causing Node.js heap exhaustion on self-hosted instances.
  - *Mitigation:* Native `Map`-based LRU cache strictly bounded to 2,000 entries (<10MB heap usage) with automatic eviction of least-recently-used entries and 6-hour TTL expiration.
- **T-13-SC [Supply Chain - ASVS V1 Architecture]:** Introduction of third-party queuing or LRU npm dependencies introducing supply chain attack vectors or maintenance overhead.
  - *Mitigation:* Zero external packages; worker pool and LRU cache implemented purely in native TypeScript primitives.
</threat_model>

<action>
Refactor `FlippRequestQueue` in apps/service/src/deals/flipp/request-queue.ts from a single-promise serialized chain to a bounded concurrency worker pool with gap pacing per D-05.

1. Constants and Options:
   - Change `MIN_GAP_MS` constant from `500` to `150` (within the 100-200ms pacing range).
   - Define `DEFAULT_CONCURRENCY = 4`.
   - Update `RequestQueueOptions` interface to add optional `concurrency?: number`.
   - In constructor, initialize `this.options.concurrency = options.concurrency ?? DEFAULT_CONCURRENCY` and `this.options.minGapMs = options.minGapMs ?? MIN_GAP_MS`.

2. Refactor Internal State:
   - Replace `private tail: Promise<unknown>` with:
     - `private readonly queue: Array<{ url: string; resolve: (val: unknown) => void; reject: (err: unknown) => void }> = []`
     - `private activeWorkers = 0`
     - `private lastDispatchedAt = Number.NEGATIVE_INFINITY`

3. Implement Queueing & Worker Loop:
   - In `request(url: string): Promise<unknown>`:
     - If `this.isOpen`, return `Promise.reject(new CircuitOpenError(this.openUntil ?? 0))`.
     - Return new Promise with `resolve` and `reject`: push `{ url, resolve, reject }` onto `this.queue`, then call `this.drainQueue()`.
   - In `private drainQueue(): void`:
     - If `this.isOpen`:
       - Reject all tasks currently in `this.queue` with `new CircuitOpenError(this.openUntil ?? 0)`.
       - Clear `this.queue.length = 0`.
       - Return.
     - While `this.activeWorkers < this.options.concurrency && this.queue.length > 0`:
       - If `this.isOpen` trips, break and flush remaining tasks.
       - Pop `const task = this.queue.shift()`. If undefined, break.
       - Increment `this.activeWorkers += 1`.
       - Call worker runner: `this.runWorker(task).finally(() => { this.activeWorkers -= 1; this.drainQueue(); })`.
   - In `private async runWorker(task: { url: string; resolve: (val: unknown) => void; reject: (err: unknown) => void }): Promise<void>`:
     - Try `const result = await this.execute(task.url); task.resolve(result);`
     - Catch `error: unknown`: `task.reject(error);`

4. Synchronized Execution & Pacing:
   - In `execute(url: string): Promise<unknown>`:
     - Check `if (this.isOpen) throw new CircuitOpenError(this.openUntil ?? 0);`
     - Loop attempts 1 to `this.options.attempts`:
       - If `attempt > 1`, execute exponential sleep backoff.
       - Call `await this.waitForGap()`.
       - Record `const previousStartedAt = this.lastDispatchedAt;`
       - Update `this.lastDispatchedAt = this.options.now();`
       - Measure gap: `const gapMs = Number.isFinite(previousStartedAt) ? this.lastDispatchedAt - previousStartedAt : null;`
       - Dispatch HTTP GET via `this.options.get(url, { 'User-Agent': this.options.userAgent })`.
       - On HTTP 200: reset `this.consecutiveFailures = 0`, return `await response.json()`.
       - On non-200 or transport throw: save `lastError`.
     - Record failure via `this.recordFailure(url, lastError)`.
     - If circuit breaker opened (`this.isOpen`), immediately flush all waiting queue items with `CircuitOpenError`.
     - Throw `lastError ?? new FlippRequestError(url, null)`.
   - In `waitForGap()`:
     - Loop until `this.options.now() >= this.lastDispatchedAt + this.options.minGapMs`.

5. In apps/service/src/deals/flipp/request-queue.test.ts:
   - Update tests for bounded concurrency:
     - Verify up to 4 requests execute in parallel (overlapping in-flight executions).
     - Verify pacing interval enforces at least `minGapMs` (150ms) between request dispatches.
     - Verify retry exponential backoff on non-200 status codes.
     - Verify that 5 consecutive failures trip the breaker, setting `openUntil` for 30 minutes and rejecting all active and queued tasks with `CircuitOpenError`.
</action>

Implement in-memory item-detail LRU caching and concurrent candidate item resolution in apps/service/src/deals/flipp/flipp-deal-source.ts per D-06 and D-07.

1. Implement `ItemDetailLruCache`:
   - Define exported class `ItemDetailLruCache`:
     - Properties: `private readonly maxItems: number`, `private readonly ttlMs: number`, `private readonly cache = new Map<string, { data: Record<string, unknown>; expiresAt: number }>()`.
     - Constructor: `constructor(maxItems = 2_000, ttlMs = 6 * 60 * 60 * 1_000)` (6-hour TTL, 2000 max capacity per D-07).
     - Method `get(id: string, now = Date.now()): Record<string, unknown> | null`:
       - If `!this.cache.has(id)`, return `null`.
       - Retrieve entry. If `now > entry.expiresAt`, delete `id` and return `null`.
       - Re-insert `id` (delete then set) to maintain most-recently-used ordering in Map iteration.
       - Return `entry.data`.
     - Method `set(id: string, data: Record<string, unknown>, now = Date.now()): void`:
       - If `this.cache.has(id)`, delete `id`.
       - Else if `this.cache.size >= this.maxItems`: delete oldest entry: `const oldest = this.cache.keys().next().value; if (oldest !== undefined) this.cache.delete(oldest);`.
       - Set `this.cache.set(id, { data, expiresAt: now + this.ttlMs })`.
     - Method `clear(): void`: `this.cache.clear()`.
     - Getter `get size(): number`: `return this.cache.size;`.

2. Equip `FlippDealSource` with the LRU Cache:
   - Add property `private readonly detailCache: ItemDetailLruCache`.
   - Update `FlippDealSourceOptions` to optionally accept `detailCache?: ItemDetailLruCache` (useful for testing).
   - In constructor, initialize `this.detailCache = options.detailCache ?? new ItemDetailLruCache()`.

3. Concurrent Item Resolution in `listFlyerItems(flyerId: string)`:
   - Retrieve flyer roster from queue.
   - Filter candidate product items:
     - `candidates = asArray(roster['items']).map(asRecord).filter(item => typeof item['display_type'] === 'number' && PRODUCT_DISPLAY_TYPES.has(item['display_type']))`.
   - Resolve candidate items concurrently using `Promise.all`:
     - `const results = await Promise.all(candidates.map(async (item) => { ... }))`.
     - Inside map:
       - Extract `externalId = asId(item['id'])`. If null, return null.
       - If `toCents(item['price']) === null`, return `{ attempt: { merchantId: null, merchantName: null, skipped: 'no_price' } }`.
       - Check cache: `let detail = this.detailCache.get(externalId);`
       - If cache miss:
         - Request detail: `const res = asRecord(await this.queue.request(`${BASE_URL}/flipp/items/${encodeURIComponent(externalId)}`)); detail = asRecord(res['item']);`
         - Cache response: `this.detailCache.set(externalId, detail);`
       - If request throws:
         - If `error instanceof CircuitOpenError || this.queue.isOpen`, re-throw `error` immediately so `Promise.all` rejects and aborts flyer persistence per D-06!
         - Otherwise (transient item error), return `{ attempt: { merchantId: null, merchantName: null, skipped: 'detail_unavailable' } }`.
       - Extract deal fields and parse price:
         - `name = asText(detail['name']) ?? asText(item['name'])`
         - `merchantId = asId(detail['merchant_id']) ?? flyer?.merchantId ?? null`
         - `merchantName = asText(detail['merchant']) ?? flyer?.merchantName ?? null`
         - Parse price with `parsePrice(...)`.
         - Record attempt with skip reason if skipped.
         - If skipped or missing required fields, return null.
         - Build `NormalizedDeal` and return `{ deal: NormalizedDeal, attempt }`.
   - Collect all `deals` and `attempts` from resolved results.
   - Record attempts: `this.record(attempts, flyer ?? { merchantId: flyerId, merchantName: ... })`.
   - Return `deals`.

4. In apps/service/src/deals/flipp/flipp-deal-source.test.ts:

     - Verifies items are resolved concurrently.
     - Verifies second call on overlapping items reuses cache without additional network calls.
     - Verifies that tripping the circuit breaker aborts `listFlyerItems` completely with `CircuitOpenError`.
